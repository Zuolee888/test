## Java层调用native层表现及方法

![](C:\Users\zuolee\AppData\Roaming\marktext\images\a9cc85bb73f4526900ab22e0c34656a13fa6a75e.png)

```java
public static native int CheckString(String str);
```

- `public`：公开，外部可以调用
- `static`：**静态方法**，不需要 new cyberpeace 对象，直接 `cyberpeace.CheckString()` 调用（正好对上前面 onClick 里的写法）
- `native`：JNI 关键字！**这个方法没有 Java 实现！逻辑不在 dex 里面，实现在 C/C++ 写的 so 原生库中**
- `int`：返回值类型，返回整数，前面代码判断返回 `1` 就是验证成功
- `CheckString(String str)`：方法接收一个字符串参数（用户输入的内容）

✅ 关键：**dex 里只有声明，没有方法体 `{ ... }`**，真正的校验逻辑在 `libcyberpeace.so`

### static 静态代码块

```
static {
    System.loadLibrary("cyberpeace");
}
```

- `static {}`：**静态代码块**，类被加载的时候，**自动执行且只执行一次**

- `System.loadLibrary("cyberpeace")`：加载原生库

  - Android 系统会去加载 `libcyberpeace.so`
  - 规则：`loadLibrary("xxx")` → 对应文件名 `libxxx.so`
  - 作用：把 so 库加载进进程，建立 Java 层 native 方法和 C 层函数的绑定关系，这样调用 `CheckString` 才会跳转到 C 代码

```java
package com.testjava.jack.pingan2;

// `cyberpeace` 类是用来与本地代码（C/C++）交互的。
// 这个类定义了一个本地方法 `CheckString`，它将在本地库中实现，
// 该方法用于检查传入的字符串，可能用于某种字符串校验逻辑。
public class cyberpeace {

    // 本地方法声明，Java 中的 native 方法是没有实现的，
    // 其实现会在 C 或 C++ 等本地代码中定义。
    // `CheckString` 函数接收一个字符串作为参数，并返回一个整数作为校验结果。
    // 这个方法可能会返回一个标志，表示字符串是否符合某种规则或要求。
    public static native int CheckString(String str);

    // 静态代码块，程序加载时会执行这个块中的代码。
    static {
        // 在此加载本地库 `cyberpeace`，该库包含了本地方法的实现。
        // `System.loadLibrary("cyberpeace");` 将加载名为 "cyberpeace" 的本地库，
        // 这个库文件必须存在于系统的库路径中（例如，系统的 `.so` 文件、`.dll` 文件或 `.dylib` 文件）。
        System.loadLibrary("cyberpeace");
    }
}
```

### Java方法链式嵌套分析

```java
if (str.equals(new String(Base64.decode(new StringBuffer(getFlag()).reverse().toString(), 0))))
```

Java 里**表达式是从内向外逐层求值**，每个方法都会返回一个结果，这个返回值直接当成外层方法的参数。

方法调用本身是一个**表达式**，有返回值；只要类型匹配，就可以直接塞进别的方法的参数位置，天然支持嵌套。

解法:逐层从内向外拆解执行顺序

```java
// 第1步：getFlag() 最先执行，返回原始字符串
getFlag()

// 第2步：拿到字符串，传给 StringBuffer 构造器
new StringBuffer(getFlag())

// 第3步：调用 reverse() 反转字符序列，返回StringBuffer自身
new StringBuffer(getFlag()).reverse()

// 第4步：toString()，把反转后的 StringBuffer 转成 String
new StringBuffer(getFlag()).reverse().toString()

// 第5步：把这个反转后的字符串传给 Base64.decode() 做解码
Base64.decode( 上面的字符串 , 0 )

// 第6步：Base64.decode 返回字节数组 byte[]，丢给 String构造函数，生成String
new String( 解码出来的byte[] )

// 第7步：最后用 str.equals( 这个最终字符串 ) 做相等判断
str.equals( 最终得到的字符串 )
```

## 底层语法规则

1. **方法调用是表达式，有返回值**
   不是只有变量才能当参数；只要一个调用能返回符合参数类型的值，就可以直接写在参数位置。
- `Base64.decode` 的第一个参数要求是 `String`
- `xxx.toString()` 返回正好是 `String` → 可以直接填进去
1. **链式调用和嵌套调用不是一回事（区分一下）**
- 链式：`a.b().c().d()` —— `b()` 返回对象，再调用这个对象的 `c()`
- 嵌套：`f(g(h()))` —— `h()` 返回值传给 `g`，`g` 返回值传给 `f`
  你这个代码里**两种同时存在**：
  `new StringBuffer(getFlag()).reverse().toString()` 是链式；外面包着 `Base64.decode(...)` 属于嵌套传参。
1. **可读性代价**
       逆向代码经常这么写：压缩代码、减少临时变量，增加阅读难度。
       正常开发不推荐写这么深的嵌套，不好调试（中间每一步的值没法单独打印观察）。

IDA使用

1. **跳转到指定地址**
   快捷键 `G`，输入十六进制虚拟地址（如 `0x401000`）回车直达。
   场景：已知函数地址、入口点，快速定位。

2. **返回 / 前进**

   - `Esc`：返回上一个跳转位置（后退）
   - `Ctrl + Enter`：前进到下一个位置

3. **快速跳转常用位置**

   - `Ctrl + E`：跳转到程序入口点（EP）
   - `Ctrl + P`：搜索函数名并跳转
   - `Ctrl + S`：快速切换段（.text/.rdata/.data 等）
   - 双击：反汇编中所有蓝色的函数名、地址、字符串，双击直接跳转

4. **视图切换**

   - `Space`：反汇编窗口内，**图形模式 ↔ 文本模式**切换
   - `Tab`：汇编视图 ↔ 伪代码视图一键切换，光标位置对应同步

## 三、反汇编视图核心操作

### 1. 代码与数据互相转换

IDA 自动分析可能出错，需手动修正：

- `C`：将选中字节**转换为代码**（反汇编成汇编指令）
- `D`：将代码 / 字节**转换为数据**，反复按可切换字节 / 字 / 双字长度
- `U`：取消定义，变回原始未定义字节
- 适用场景：加壳、花指令导致 IDA 把代码误识别成数据，手动按 `C` 恢复。

### 2. 创建函数

光标放在函数起始地址，按 `P`，IDA 会自动分析函数边界、生成函数对象。

- 只有被识别为函数的代码，才能使用 `F5` 生成伪代码、打开图形视图。
- 适用场景：自动分析漏识别的函数、脱壳后手动重建函数。

### 3. 标注与注释

逆向是 “边分析边做笔记” 的过程，这两个操作能大幅提升后续效率：

- **重命名**：光标放在函数名、变量名、标签上，按 `N` 输入自定义名称。
  例：识别出加密函数后改名为 `encrypt_func`，后续调用处会同步更新。

- **添加注释**

  - `:`：普通注释，仅在当前行显示
  - `;`：可重复注释，所有引用该地址的位置都会显示
